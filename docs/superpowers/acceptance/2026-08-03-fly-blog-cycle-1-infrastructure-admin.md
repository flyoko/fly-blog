# fly living 周期 1 验收标准：基础设施与后台骨架

- 日期：2026-08-03
- 状态：待用户批准
- 依据：`docs/superpowers/specs/2026-08-03-fly-blog-content-platform-design.md`
- 范围：周期 1，不包含自述前台、瞬间前台、AI 阅闻、天气、随心听和全站最终动效落地

## 1. 验收原则

1. 每个验收项必须能够通过浏览器操作、自动化测试、Cloudflare/GitHub 配置截图或命令输出进行验证。
2. 不以“代码已经编写”作为完成依据，必须验证真实行为和失败路径。
3. 生产站点 `flyovo.cc.cd`、备用 Pages 域名和现有 Twikoo 服务在整个周期内保持可用。
4. 开发过程不重新克隆、不覆盖当前仓库，不提交或推送任何开发改动，除非用户另行明确授权。
5. 产品功能中的 Git Commit、分支和 Pull Request 行为只在测试仓库或用户明确授权的目标仓库环境中验证。

## 2. 基础资源与仓库

### AC-01 私有仓库可见性

**给定** `flyoko/fly-blog` 已完成私有化，
**当** 未登录或无权限账号访问仓库地址，
**那么** 无法查看代码、提交历史和文件，也无法新建公开 Fork；已授权的 `flyoko` 仍可正常访问。

### AC-02 现有生产站点不受仓库私有化影响

**给定** 仓库已经私有化，
**当** 访问 `https://flyovo.cc.cd/` 和 `https://fly-living.pages.dev/`，
**那么** 两个地址均返回成功响应并能加载当前公开内容。

### AC-03 独立内容数据库

**给定** Cloudflare 账户中已有 Twikoo 使用的 D1，
**当** 周期 1 资源创建完成，
**那么** 存在独立的 `fly-living-content` D1 数据库，后台会话、审计和平台数据不会写入 Twikoo 数据库。

### AC-04 R2 媒体存储桶

**给定** R2 已开通，
**当** 查看 Cloudflare 资源，
**那么** 存在 `fly-living-media` 存储桶，并完成 Worker 绑定；生产媒体通过 `media.flyovo.cc.cd` 访问，不依赖公开的 `r2.dev` 地址。

### AC-05 API Worker 隔离

**给定** 现有 `fly-living-edge` 负责正式域名入口，
**当** 周期 1 部署完成，
**那么** 存在独立 `fly-living-api` Worker；边缘 Worker 只负责站点代理和 `/api/*` 路由转发，业务逻辑不与站点代理代码混杂。

### AC-06 同源 API

**给定** 浏览器访问正式域名，
**当** 后台请求会话、文章、媒体或发布状态，
**那么** 请求使用 `https://flyovo.cc.cd/api/...` 同源地址，不需要浏览器跨域访问独立 API 域名。

## 3. GitHub 登录与会话安全

### AC-07 未登录访问后台

**给定** 用户没有有效后台会话，
**当** 访问 `/admin` 或任意后台子页面，
**那么** 可以看到登录入口，但不会返回私有文章、仓库结构、媒体列表或发布记录。

### AC-08 GitHub 登录成功

**给定** 用户使用允许的 GitHub 账号 `flyoko`，
**当** 完成 GitHub 登录回调，
**那么** 系统创建后台会话并跳转至后台概览页，页面显示已登录账号但不显示 GitHub Token。

### AC-09 非允许账号被拒绝

**给定** 用户使用不是 `flyoko` 的 GitHub 账号，
**当** 完成 GitHub 登录回调，
**那么** 系统拒绝创建管理员会话，返回明确的无权限提示，并记录不含敏感 Token 的安全审计事件。

### AC-10 用户名与不可变 ID 双重校验

**给定** 允许账号配置包含 GitHub 用户名和用户 ID，
**当** 登录回调被处理，
**那么** 后端同时验证两者；仅用户名相同但用户 ID 不匹配时登录失败。

### AC-11 Cookie 安全属性

**给定** 登录成功，
**当** 检查会话 Cookie，
**那么** Cookie 至少包含 `HttpOnly`、`Secure` 和 `SameSite=Lax`，浏览器 JavaScript 无法读取会话值。

### AC-12 会话过期与退出

**给定** 用户已登录，
**当** 会话过期或用户主动退出，
**那么** 后续管理员 API 返回未认证状态，后台跳转到登录页，旧会话不能继续写入数据。

### AC-13 CSRF 防护

**给定** 用户拥有有效会话，
**当** 写请求缺失或携带错误 CSRF Token，
**那么** API 拒绝该请求，且不产生 Git、D1 或 R2 写入。

### AC-14 Secret 不泄露

**给定** 系统已配置 GitHub App、R2、D1 和部署凭据，
**当** 检查仓库、静态产物、浏览器网络响应和构建日志，
**那么** 不出现私钥、Client Secret、安装 Token、R2 凭据或 Cloudflare API Token。

## 4. 后台骨架与视觉

### AC-15 后台一级导航

**给定** 管理员登录后台，
**当** 查看左侧导航，
**那么** 至少显示：概览、文章、瞬间、AI 阅闻、自述、媒体库、随心听、模块管理、发布与审核、站点设置。

### AC-16 周期 1 未实现模块的状态

**给定** 周期 1 不实现全部业务模块，
**当** 打开瞬间、AI 阅闻、自述、随心听等入口，
**那么** 页面显示清晰的“后续周期开放”状态或受控占位页，不出现空白、404 或伪造数据。

### AC-17 70/30 视觉基准

**给定** 后台概览页，
**当** 在桌面端查看，
**那么** 页面保留高密度工作台结构，并使用已确认的渐变欢迎区、柔和卡片和轻量反馈；视觉装饰不会遮挡表格、编辑器和操作按钮。

### AC-18 主题模式

**给定** 后台已加载，
**当** 切换浅色、深色或跟随系统模式，
**那么** 所有周期 1 页面均保持可读，设置在刷新后仍然生效。

### AC-19 减少动态效果

**给定** 操作系统开启 `prefers-reduced-motion`，
**当** 访问后台，
**那么** 页面切换、卡片和通知移除非必要位移或持续动画，功能不受影响。

### AC-20 响应式后台

**给定** 桌面、平板和手机宽度，
**当** 访问登录页、概览、文章列表、编辑器和媒体库，
**那么** 关键操作可用，无横向页面溢出；手机端允许将复杂三栏编辑器切换为分步或抽屉布局。

## 5. 概览与系统状态

### AC-21 概览真实数据

**给定** 管理员进入概览页，
**当** 系统成功读取数据，
**那么** 文章数量、最近内容、待审核变更、媒体数量和最近部署状态来自真实 API，而不是写死的原型数字。

### AC-22 服务健康状态

**给定** GitHub、D1、R2 和部署服务均可用，
**当** 查看概览，
**那么** 显示各服务最近一次检查时间和正常状态。

### AC-23 服务异常提示

**给定** 任意一个依赖服务不可用，
**当** 概览刷新，
**那么** 后台标明具体服务、失败时间和可重试操作，不把整个后台渲染成空白页。

## 6. 文章读取与编辑

### AC-24 文章列表读取

**给定** 私有仓库中存在符合当前 Nuxt Content 结构的文章，
**当** 打开文章管理，
**那么** 后台显示标题、路径、分类、标签、发布日期和草稿状态，并支持搜索和基本筛选。

### AC-25 文章内容加载

**给定** 选择一篇文章，
**当** 编辑器加载，
**那么** Markdown 正文和 Frontmatter 被正确解析到编辑区与元数据表单，未知但合法的 Frontmatter 不会在未提示的情况下丢失。

### AC-26 新建文章

**给定** 管理员点击新建文章，
**当** 填写标题、正文、分类、标签和日期，
**那么** 系统生成符合项目约定的文件路径和 Frontmatter，并在提交前显示最终预览。

### AC-27 Markdown 预览

**给定** 正在编辑文章，
**当** 修改 Markdown，
**那么** 预览能够正确显示项目支持的标题、列表、代码块、图片、链接和扩展语法；预览错误不会清空正文。

### AC-28 草稿保护

**给定** 编辑器中存在未提交修改，
**当** 浏览器刷新、意外关闭或登录会话过期，
**那么** 本地草稿可以恢复，并明确区分“本地未提交草稿”和“仓库中的正式草稿”。

### AC-29 Frontmatter 校验

**给定** 必填字段为空、日期格式错误或分类不存在，
**当** 尝试发布，
**那么** 后台阻止提交，并把错误定位到具体字段。

### AC-30 Git 路径白名单

**给定** 客户端尝试把文章写入允许目录之外，或提交包含路径穿越的文件名，
**当** API 处理写请求，
**那么** 请求被拒绝，不修改仓库任何文件。

### AC-31 冲突检测

**给定** 管理员打开文章后远端内容已发生变化，
**当** 管理员保存旧版本，
**那么** 后端检测 Git SHA 冲突，拒绝覆盖，并提供重新加载或比较差异的选项。

## 7. Git 直接发布

### AC-32 普通文章直接发布

**给定** 文章通过结构校验且管理员选择直接发布，
**当** 提交成功，
**那么** GitHub App 在目标分支创建单个可追踪 Commit，后台显示 Commit 标识和构建状态。

### AC-33 Commit 内容最小化

**给定** 只修改一篇文章，
**当** 直接发布，
**那么** Commit 只包含预期文章及必要的受控元数据文件，不混入本地工作区其他改动。

### AC-34 构建失败不伪装成功

**给定** Git Commit 已创建但 CI 构建失败，
**当** 后台查询发布状态，
**那么** 状态显示“提交成功、部署失败”，提供失败步骤和重试入口，不显示“已上线”。

### AC-35 生产部署完成

**给定** CI 检查全部通过，
**当** Wrangler Direct Upload 完成，
**那么** 后台显示部署成功，正式域名可访问新文章，现有域名和 Pages 项目未被替换。

## 8. Pull Request 工作流

### AC-36 高影响配置默认走 PR

**给定** 管理员修改分类、导航、模块、页脚、天气城市或资讯源配置，
**当** 点击保存，
**那么** 系统默认创建独立分支和 Pull Request，不直接写入生产分支。

### AC-37 PR 差异可查看

**给定** PR 已创建，
**当** 在后台打开详情，
**那么** 能看到受影响文件、结构化差异、Commit、检查状态和 GitHub PR 链接。

### AC-38 PR 预览

**给定** PR 检查通过，
**当** 预览部署完成，
**那么** 后台展示可访问的非生产预览地址，且预览不会覆盖正式站点。

### AC-39 失败 PR 不可误合并

**给定** PR 的 lint、类型检查、生成或链接检查失败，
**当** 管理员尝试从后台合并，
**那么** 系统阻止默认合并操作并明确显示失败检查。

### AC-40 PR 合并后生产部署

**给定** PR 检查通过并被管理员确认合并，
**当** 生产流水线结束，
**那么** 后台把 PR、合并 Commit 和生产部署关联展示，并更新最终状态。

## 9. R2 媒体库

### AC-41 媒体上传

**给定** 管理员在媒体库选择允许的图片或音频文件，
**当** 上传完成，
**那么** 文件写入正确的 R2 前缀，后台返回稳定媒体 URL、MIME、大小和上传时间。

### AC-42 文件校验

**给定** 文件扩展名与真实内容不符、类型不允许或超过限制，
**当** 上传，
**那么** 后端拒绝文件并返回具体原因，不在 R2 中留下可公开访问的残留对象。

### AC-43 多文件部分失败

**给定** 一批文件中部分合法、部分非法，
**当** 批量上传，
**那么** 后台逐项显示成功或失败结果，成功文件可继续使用，失败文件可单独重试。

### AC-44 媒体列表与筛选

**给定** R2 已有多种媒体，
**当** 打开媒体库，
**那么** 可以分页查看并按类型、时间和名称筛选，不需要一次加载整个存储桶。

### AC-45 插入文章

**给定** 文章编辑器打开媒体选择器，
**当** 选择一张已上传图片，
**那么** 编辑器插入正确的 Markdown 或项目图片语法，预览能够显示该图片。

### AC-46 回收站删除

**给定** 管理员删除媒体，
**当** 确认删除，
**那么** 对象进入 `trash/` 或等效回收状态而不是立即永久删除，并可在保留期内恢复。

### AC-47 引用保护

**给定** 媒体仍被已发布文章引用，
**当** 尝试永久删除，
**那么** 后台阻止删除或要求显式高风险确认，并列出至少一个引用位置。

## 10. 审计、状态和恢复

### AC-48 审计日志

**给定** 管理员执行登录、上传、发布、创建 PR、删除或恢复操作，
**当** 操作结束，
**那么** D1 审计日志记录操作者、动作、目标、结果、时间和关联 ID，不记录 Secret 或完整 OAuth Token。

### AC-49 发布记录关联

**给定** 一次 Git 发布或 PR 发布完成，
**当** 打开发布与审核页面，
**那么** 可以从一个记录追踪到 Commit、PR、CI 运行和 Pages 部署结果。

### AC-50 API 幂等与重复点击

**给定** 管理员因网络延迟重复点击发布或上传，
**当** 相同幂等键的请求重复到达，
**那么** 系统不会创建重复 Commit、重复 PR 或重复媒体对象。

### AC-51 网络失败保留编辑内容

**给定** 保存或发布时发生网络中断，
**当** API 返回失败或超时，
**那么** 编辑器内容仍然存在，页面提供重试，不自动跳转或清空表单。

### AC-52 API 错误格式统一

**给定** 管理员 API 发生认证、校验、冲突、限流或内部错误，
**当** 前端接收错误，
**那么** 响应包含稳定错误码、可读消息和请求追踪 ID，前端按类型展示恰当反馈。

### AC-53 速率限制

**给定** 登录、上传或写接口短时间收到异常大量请求，
**当** 超过配置阈值，
**那么** Worker 返回限流响应，不继续消耗 GitHub、R2 或 D1 写额度，正常低频使用不受影响。

## 11. CI、质量与兼容性

### AC-54 PR 和生产检查

**给定** 任意后台生成的 Git 变更，
**当** CI 运行，
**那么** 至少执行依赖安装、`pnpm lint`、类型检查、`pnpm generate` 和内部链接检查；任一步失败均阻止对应发布流程完成。

### AC-55 自动化测试

**给定** 周期 1 代码完成，
**当** 执行测试套件，
**那么** 至少覆盖身份校验、会话、CSRF、路径白名单、文章转换、Git 发布策略、R2 校验和 API 错误格式。

### AC-56 端到端核心路径

**给定** 可隔离的测试环境，
**当** 执行浏览器端到端测试，
**那么** 自动验证：登录、文章读取、编辑、直接发布、配置创建 PR、媒体上传、插入图片、查看部署状态和退出登录。

### AC-57 无障碍基础

**给定** 使用键盘操作后台，
**当** 遍历登录、导航、编辑、上传和发布流程，
**那么** 关键控件可聚焦、焦点可见、表单有标签，主要操作不依赖鼠标悬停。

### AC-58 现有站点回归

**给定** 周期 1 部署完成，
**当** 回归首页、文章详情、归档、友链、RSS 和 Twikoo 评论，
**那么** 现有公开功能无阻断性回归，正式域名与备用域名均能访问。

### AC-59 源码信息处理边界

**给定** 周期 1 聚焦基础设施，
**当** 检查公开站点，
**那么** 不新增任何私有仓库或后台源码入口；已有“本站源码”和主题链接的最终清理允许放到公开站点视觉周期，但实施计划必须明确其归属，不能遗失。

## 12. 周期 1 完成定义

周期 1 只有在以下条件全部满足时才可标记完成：

1. AC-01 至 AC-59 均有明确结果，阻断项全部通过。
2. GitHub、Cloudflare 和浏览器端验证证据已整理。
3. `pnpm lint`、类型检查、`pnpm generate`、链接检查和自动化测试全部通过。
4. 正式站点、备用 Pages 域名和 Twikoo 服务保持可用。
5. 没有 Secret 写入仓库、前端产物或日志。
6. 文章直接发布、配置 PR 发布和 R2 媒体上传三条核心链路在隔离测试环境成功演示。
7. 所有已知限制、人工配置步骤和回滚步骤写入运维文档。
8. 用户完成周期 1 验收后，才进入周期 2“自述与瞬间”的实现流程。

## 13. 验收证据清单

最终验收报告至少附带：

- 私有仓库权限验证结果
- GitHub App 权限和安装范围截图或导出说明
- Worker、D1、R2 绑定清单
- 会话 Cookie 属性和未授权 API 响应
- 文章直接发布的 Commit 与部署记录
- 配置修改的 PR、检查和预览记录
- 媒体上传、引用、回收和恢复记录
- 审计日志样例（敏感字段已脱敏）
- CI 和自动化测试结果
- 桌面与移动端后台截图
- 正式站点、备用站点和 Twikoo 回归结果
