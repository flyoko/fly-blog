# 虚拟模块插件配置必须验证最终绑定

## 问题特征

Nuxt 配置中已经声明 Remark 或 Rehype 插件，依赖也已安装，构建仍然成功，但运行时 Markdown 输出完全没有插件效果。例如单回车没有生成换行，数学、emoji 或自定义元数据处理也可能同时失效。

只断言配置文件包含插件名称会产生假阳性，因为配置还要经过模块代码生成、虚拟模块求值和运行时导入才能真正进入 unified 管线。

## 非显然根因

对第三方模块的补丁在生成插件对象时输出了字面量简写 `{ instance }`，而不是把计算出的导入符号写入生成代码。虚拟模块加载时因此求值失败，MDC 解析器又对 `#mdc-imports` 使用容错导入，最终静默退化为“没有任何插件”，构建过程不会直接报错。

插件导入成功不等于插件实例已经绑定；补丁源码看起来合理也不等于生成结果正确。

## 可执行规则

1. 修改代码生成器或补丁后，必须检查生成的虚拟模块，确认每个插件对象引用真实导入符号，例如 `instance: _RemarkBreaks`。
2. 回归测试必须断言可观察的解析结果，例如单回车生成 `<br>`，不能只搜索 Nuxt 配置中的插件名称。
3. 运行时会在浏览器解析 Markdown 时，插件入口应使用浏览器安全的 JavaScript 模块；需要 Node 加载器的 TypeScript 插件不得直接进入客户端包。
4. 更新 pnpm 补丁后确认 lockfile 中 patched dependency 哈希同步变化，并重新执行安装与 `nuxt prepare`。
5. 多个插件同时失效时，优先检查共享虚拟模块的生成与求值，不要逐个怀疑插件实现。

## 诊断步骤

- 打开 `.nuxt/mdc-imports.mjs`，比较 import 名称与 `remarkPlugins` / `rehypePlugins` 中的实例表达式。
- 直接调用 MDC 解析器或在真实预览组件中输入最小样例，检查 AST/DOM 是否发生预期转换。
- 搜索运行时对虚拟模块导入的 `catch` 或 fallback；静默容错可能掩盖模块求值错误。
- 临时移除补丁并比较生成代码，定位是上游行为、补丁还是插件入口格式导致失效。

## 不适用场景

- 纯构建期插件且生成产物不会在浏览器重新解析时，可以只验证服务端输出，但仍应检查最终生成的绑定。
- 插件本身按条件跳过某些节点时，应使用符合触发条件的最小样例，不能把正常跳过误判为未加载。

## 证据

提交 `985d9bca6615fbc3301b0dbc586eeb3ffa8171f7` 修复了 `@nuxtjs/mdc` 补丁中的实例表达式，加入 `remark-breaks`，并用浏览器回归证明编辑预览和公共文章中的单回车都会生成换行。完整 `pnpm verify` 与编辑器 E2E 通过。
