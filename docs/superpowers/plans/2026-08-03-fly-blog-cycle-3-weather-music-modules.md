# fly living 周期 3 实施计划：天气、随心听与模块管理

## 目标
在周期 1/2 的 Git/R2/D1/Worker/后台基础上，交付固定城市天气、歌单管理、全局播放器和可视化模块管理，并完成测试、推送和生产部署。

## 约束
- 天气不读取访客定位；城市由站长在后台选定。
- Open-Meteo 通过 Worker 适配，浏览器不直连天气服务。
- 歌单存私有 Git，音频/封面存 R2 或合法公开 URL。
- 天气与模块配置默认 PR；歌单条目属于低风险内容，可直接 Git Commit。
- 不抓取受保护流媒体地址，不在仓库/日志输出 Secret。

## 任务

### Task 1：定义天气、歌单和播放器契约
- 扩展天气配置启用态校验。
- 新增公开天气、城市搜索、歌单与播放器状态 schema。
- 增加 URL 安全和排序测试。

### Task 2：新增天气持久化迁移
- 创建天气快照/同步状态表。
- 保存最后成功响应、上游时间、获取时间和错误。
- 为缓存版本和最近成功查询建立索引。

### Task 3：实现 Open-Meteo 适配器
- 地理编码搜索限制数量、超时和字段映射。
- Forecast 当前/日高低/昼夜/天气码映射。
- 生成生活提示、来源署名与更新时间。
- 限制仅请求配置城市坐标。

### Task 4：实现天气 API、缓存与降级
- `GET /api/weather` 公开读取。
- `GET /api/admin/weather/search` 管理员城市搜索。
- 30 分钟新鲜缓存和 24 小时 stale fallback。
- 写同步状态与错误，不以失败清空快照。

### Task 5：实现歌单 Git 服务
- 创建 `content/playlists/default.json` 初始内容。
- GitHub Repository 读取/原子提交、SHA 冲突和审计。
- `GET/PUT /api/admin/music/playlist` 管理 API。
- `GET /api/music/playlist` 公开只读 API 或构建期安全数据入口。

### Task 6：实现后台随心听
- 歌曲增删改、启停、排序。
- 音频/封面媒体选择器与上传目的。
- 表单校验、保存反馈、冲突恢复和合法来源提示。

### Task 7：实现全局播放器 Store 与组件
- Pinia 队列、当前曲目、模式、音量、进度和持久化。
- Audio 事件、错误跳过、用户交互播放。
- 控制条、展开面板、键盘/ARIA 和 reduced-motion。
- 接入默认布局，路由切换不中断。

### Task 8：实现天气公开组件
- 右侧栏天气卡片、昼夜状态、最高/最低和更新时间。
- stale/不可用状态、Open-Meteo 署名。
- 桌面与移动侧栏适配。

### Task 9：实现模块管理
- `/admin/modules` 可视化开关和排序。
- 连续顺序归一化和 schema 校验。
- 创建受控模块配置 PR。
- 删除周期 3 占位状态。

### Task 10：扩展站点设置天气表单
- 城市搜索与候选选择。
- 显示经纬度/时区但不要求手填。
- 创建天气配置 PR并链接审核页。

### Task 11：测试与质量门禁
- Nuxt/共享/Worker 单元测试。
- E2E 覆盖天气、歌单、播放器、模块 PR、移动端。
- `pnpm verify`、`pnpm test:e2e`、链接和 Secret 扫描。

### Task 12：生产部署与验收
- 提交并推送周期 3 分支与私有 `main`。
- 等待 Quality、Pages、Workers 成功。
- 生产城市搜索/天气缓存、歌单保存/播放、模块 PR 演练。
- 清理探针媒体、Commit/PR、D1 数据和分支。
- 更新运维与周期 3 验收报告。
