# fly living 市场雷达与财经多源聚合设计

- 日期：2026-08-23
- 状态：已完成设计自审，待用户审阅
- 项目：`flyoko/fly-blog`
- 目标部署：Cloudflare Pages + Hono Workers + D1/R2 + GitHub Actions
- 约束：不依赖常驻 VPS，不引入 Spring Boot/MySQL，不把完整 `daily_stock_analysis` 原样部署到 Cloudflare

## 1. 背景与目标

`flyovo.cc.cd` 已有 AI 阅闻与财经 7×24，并具备 Cloudflare Worker、D1、R2、Cron 和 GitHub Actions。现有财经 7×24 主要依赖华尔街见闻单一来源，按 `source_id + upstream id` 存储，只能解决单来源内重复，无法处理多个媒体对同一事件的重复报道。

本次设计目标：

1. 新增 `/market` 市场雷达，帮助快速判断大盘强弱、资金主线、自选异动和近期信号。
2. 将 `/ai.news` 中的财经 7×24 升级为多源聚合，但同一财经事件只展示一条规范事件。
3. 对桌面端、平板和移动端分别优化信息密度，不把桌面时间轴机械压缩到手机。
4. 完整复用博客现有浅色、深色、动态背景、玻璃表面和 reduced-motion/reduced-transparency 体系。
5. 盘中任务留在 Cloudflare Worker；财报、历史回填和日线级重任务交给 GitHub Actions。
6. 任何外部数据源失败时显示最后成功数据和过期状态，绝不生成模拟行情或模拟新闻。

## 2. 已确认产品边界

第一阶段只做直接改善炒股效率的能力：

1. 板块/概念实时资金排名。
2. 3/5/10/20 日累计资金流与持续性排名。
3. 自选股雷达。
4. 三大指数与市场宽度。
5. 财经多源 7×24 + 自选股/板块关联。
6. 财报条件筛选器。

第二阶段增加：

- 5 分钟级异常放量/做 T 观察信号。
- 技术指标告警。
- AI/规则信号的 T+1/T+3/T+5/T+10 结果追踪。

暂不做：

- Level 2、真实五档盘口、逐笔 Tick/HFT。
- 自动下单。
- 全市场分钟 K 长期存储。
- 完整 `daily_stock_analysis` Python 服务。
- `git-finance-dashboard` 的 Spring Boot/MySQL/JWT/模拟盘口。

## 4. 财经 7×24 多数据源策略

### 4.1 来源收敛：少而精

财经 7×24 不追求来源数量，当前生产收敛到三个互补实时媒体源，并把官方披露作为独立事件类型：

**P0 实时媒体源**

- **华尔街见闻**：保留现有 Worker Adapter，继续作为已上线基线来源。它不是长期唯一依赖，来源状态必须可单独关闭和降级。
- **金十数据 MCP**：官方 MCP 已用用户提供的 Token 实测 `list_flash` 成功返回当前 7×24 快讯，技术链路可用。正式代码只读取 `JIN10_MCP_TOKEN` Cloudflare Secret，不写入仓库、日志、D1 或前端。由于金十公开用户协议限制未经书面许可的复制、整理和源页面外展示，默认 `publicDisplay=false`：在取得可公开聚合的授权前，只允许作为 P0 可用性验证、后台/私有决策和跨源事件校验来源，不在公开 `/ai.news` 直接转载其快讯正文。

- **财联社电报**：通过财联社 Web 电报使用的结构化滚动接口读取 `id/ctime/title/brief/level/subjects/shareurl`，只保存财经聚合所需的标题、短摘要、时间、分类、重要级别与原文链接；A/B 级映射为“重要”。生产 Adapter 为 `cls-telegraph-7x24`，每 5 分钟与其他财经来源独立同步。
- **新浪财经 iNews**：2026-08-24 已明确取消并退役，不再作为候选来源，不再配置凭据，也不再进入 `syncAll()`。

**官方事件源**

- 巨潮资讯、上交所、深交所、证监会后续以 `official-disclosure` / `regulatory` 类型加入，优先用于自选股公告、监管和政策事件。它们不参与“媒体源越多越好”的竞争，也不要求和媒体快讯一一对齐。

当前不接东方财富等额外媒体快讯源；新浪财经已退役。来源优先级固定为金十 > 财联社 > 华尔街见闻，同一事件只生成一个 canonical 事件并保留全部来源链接。

### 4.2 内容保存边界

本站只保存和展示：

- 标题。
- 必要的短摘要。
- 发布时间。
- 分类/主题。
- 关联股票/行业/概念。
- 来源名称和原文链接。

默认不镜像第三方完整文章。多源聚合用于事件发现与归并，不将外部媒体内容伪装成本站原创。

## 5. 多源去重模型

现有 `finance_flash_items` 以来源条目为中心。多源后改为“规范事件 + 来源引用”。

### 5.1 `finance_events`

```sql
CREATE TABLE finance_events (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  summary TEXT,
  published_at TEXT NOT NULL,
  first_seen_at TEXT NOT NULL,
  category TEXT NOT NULL,
  category_label TEXT NOT NULL,
  topic TEXT,
  important INTEGER NOT NULL DEFAULT 0,
  importance_score REAL,
  primary_source_id TEXT NOT NULL,
  primary_source_name TEXT NOT NULL,
  primary_source_url TEXT,
  source_count INTEGER NOT NULL DEFAULT 1,
  dedupe_confidence REAL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 5.2 `finance_event_sources`

每个上游原始条目保留一条来源记录，不因聚合丢失出处。

```sql
CREATE TABLE finance_event_sources (
  id TEXT PRIMARY KEY,
  event_id TEXT NOT NULL,
  source_id TEXT NOT NULL,
  source_item_id TEXT NOT NULL,
  source_name TEXT NOT NULL,
  source_url TEXT,
  title TEXT NOT NULL,
  summary TEXT,
  published_at TEXT NOT NULL,
  normalized_title TEXT NOT NULL,
  title_fingerprint TEXT NOT NULL,
  raw_hash TEXT NOT NULL,
  fetched_at TEXT NOT NULL,
  UNIQUE(source_id, source_item_id)
);
```

### 5.3 `finance_event_entities`

```sql
CREATE TABLE finance_event_entities (
  event_id TEXT NOT NULL,
  entity_type TEXT NOT NULL,
  entity_key TEXT NOT NULL,
  entity_name TEXT NOT NULL,
  relevance REAL NOT NULL,
  PRIMARY KEY(event_id, entity_type, entity_key)
);
```

实体类型第一阶段：`stock`、`sector`、`concept`、`macro`。

## 6. 去重算法

去重不依赖 LLM，分四级执行。

### 6.1 L0：来源内唯一键

`source_id + source_item_id` 完全相同：直接视为同一来源条目的更新。

### 6.2 L1：规范标题指纹

标题先做：

- Unicode NFKC。
- 全半角统一。
- 去多余空白。
- 去常见来源前后缀，例如“快讯：”“某媒体：”。
- 统一中文/英文标点。
- 保留关键数字、百分比、公司名、股票代码。

规范化结果完全相同或指纹相同时，在合理时间窗内直接合并。

### 6.3 L2：近似标题

只从同分类、发布时间前后 120 分钟的近期事件中找候选，避免全表相似度扫描。

Worker 对中文标题生成字符 bigram/trigram 集合，计算 Jaccard 相似度，并结合：

- 共同股票/行业/概念实体。
- 共同核心关键词。
- 发布时间距离。
- 来源是否互相独立。

建议初始阈值：

- `>= 0.84` 且实体/关键词一致：自动合并。
- `0.76 ~ 0.84`：默认不合并，除非存在稳定事件键。
- `< 0.76`：保持独立。

阈值必须通过真实样本回放调优，不能硬编码后直接宣称正确。

### 6.4 L3：冲突保护

出现以下任一情况时，不允许仅凭文本相似自动合并：

- 关键金额、百分比、利率、产量等数字存在明显冲突。
- “上涨/下跌”“增持/减持”“盈利/亏损”等方向词相反。
- 公司主体不同。
- 一个是预测，一个是正式结果。

宁可保留两条，也不要错误合并两件不同事件。

### 6.5 规范事件选择

事件时间使用最早可信发布时间；展示标题按以下顺序评分：

1. 正式/结构化来源优先。
2. 信息完整度更高。
3. 标题更明确、无营销前缀。
4. 来源优先级相同时取较早版本。

页面只展示一条事件，在底部显示：

```text
华尔街见闻 · 另有 2 个来源
```

展开后可以查看各来源及原文，不重复占据主信息流。

## 11. `/market` 独立黑金视觉域

用户已确认：点击“市场”后允许与博客其他页面存在明确视觉差异。`/market` 使用“专业交易终端 × fly living”黑金皮肤，但差异必须局限在市场路由内部，文章、AI 阅闻、瞬间、自述、友链、归档、留言和管理后台继续使用现有博客主题。

实现原则：

- 不修改 `:root`、`.light`、`.dark`、`.dynamic` 的全局主题语义。
- `/market` 根节点使用 `.market-terminal` 建立局部 token，例如 `--market-bg`、`--market-panel`、`--market-gold`、`--market-line`、`--market-text-*`。
- 黑金色板以炭黑、石墨灰、低饱和香槟金为主；金色只表示主线、焦点、选中态和可信信号，不承担所有强调色。
- A 股涨跌继续使用红涨绿跌的证券语义，不用金色替代涨跌方向。
- 全站 `BlogTopNav`、站点 Logo、侧栏/移动导航结构保持不变；进入 `/market` 后正文区域切换为交易终端皮肤，从而保留“仍在 fly living 内”的连续性。
- 不把黑金 token 注入其他路由，也不让市场页组件样式依赖全局元素选择器。

### 11.1 动效与可访问性

- 市场页允许低频扫描线、高光扫过或数字状态过渡，但不得增加持续闪烁、频繁粒子或高频 transform 动画。
- `prefers-reduced-motion: reduce` 时关闭扫描、高光位移、shimmer 和非必要图表动效。
- `prefers-reduced-transparency: reduce` 时市场面板使用实体炭黑/石墨背景，不依赖 `backdrop-filter`。
- 进入和离开 `/market` 不修改全局 color-mode 状态；返回任一博客页面后视觉必须完全恢复原状。

### 11.2 性能约束

- 不全局引入 Element Plus。
- 图表库只在 `/market` 路由懒加载；若使用 ECharts，仅引入 `echarts/core` 所需模块。
- 财经列表不依赖图表库。
- 数据刷新优先更新数据状态，不重建整页组件树。
- 后台轮询不可触发页面布局跳动。

## 13. 同步、缓存与失败处理

### 13.1 财经来源

每个来源独立维护：

- `last_success_at`
- `last_attempt_at`
- `status`
- `item_count`
- `last_error`
- `next_sync_at`
- `latency_ms`

来源失败：

- 不删除其他来源数据。
- 不清空规范事件。
- 继续展示最近一次成功快照。
- 管理后台标记来源 degraded/failed。

### 13.2 市场数据

市场数据统一返回：

```ts
{
  data,
  source,
  fetchedAt,
  marketAt,
  stale,
  staleAgeMs,
  quality
}
```

所有源失败时只返回最后成功快照，并明确 `stale: true`。

## 14. 管理后台

现有“财经内容”和“来源健康”继续保留并扩展：

- 按来源筛选。
- 查看规范事件下的全部来源。
- 查看自动去重原因/置信度。
- 手动“拆分错误聚合”。
- 手动“合并明显重复事件”。
- 来源健康、最近延迟、错误率。

人工修正必须持久化，后续同步不能再次自动把已人工拆分的事件合回去。

## 15. P0 可行性验收

在做完整 UI 前先验证生产 Cloudflare Worker 能否稳定取数。

### 15.1 数据源

P0 分为“立即可测”和“凭据就绪后可测”两组。

立即可测：

- 华尔街见闻现有接口。
- 财联社电报结构化滚动接口。
- 金十官方 MCP `list_flash`；开发阶段凭据只存在 Secret/本地受控环境。
- 市场行情与板块资金候选接口。

连续至少 5 个交易日记录：

- 请求成功率。
- 空数据率。
- P50/P95 延迟。
- 429/403/5xx。
- 字段结构变化。
- Cloudflare 节点是否被上游限制。

生产准入建议：

- 个股/指数成功率 `>= 99%`。
- 板块资金成功率 `>= 98%`。
- 财经单来源成功率 `>= 98%`，且至少两源组合后系统可用性明显高于单源。
- P95 `< 3s`。
- 不得产生模拟值。

未达到标准的来源降级为 Tier B/C，不阻止其他来源上线。

### 15.2 去重

构造跨来源真实样本集并人工标注。

目标：

- 自动合并 precision `>= 98%`，优先控制误合并。
- 重复事件漏合并率 `<= 10%`，后续再逐步提高 recall。
- 含冲突数字或反向语义的样本不得自动错误合并。
- 所有自动合并都可以追溯来源和打分依据。

## 18. 回滚

1. 多源聚合可以通过 `market/finance` 模块开关关闭，恢复单一来源展示。
2. 新 canonical 表与原 `finance_flash_items` 迁移阶段并存，切换完成前不破坏旧 API。
3. 任一新来源可独立禁用。
4. `/market` 可独立隐藏，不影响 `/ai.news`、文章、瞬间和其他博客页面。
5. 路由级图表代码与主站 bundle 隔离，回滚市场页不会影响博客核心路由。

## 19. 设计自审

- 无未决占位符。
- 多源财经不再使用 `source_id + id` 作为跨源去重方案。
- 去重不依赖 LLM，适合 Worker CPU/成本约束。
- 来源分层明确，未把未验证公开接口承诺为稳定生产接口。
- 移动端与桌面端不是简单缩放关系，明确了小屏单列规则。
- 主题、动效、透明度和 MacBook 闪烁风险已纳入设计。
- `/market` 与财经 7×24 职责区分明确：市场页负责决策雷达，财经页负责事件流。
- 盘中与盘后任务边界符合无常驻服务器部署形态。
- 安全、回滚、数据质量、测试与验收范围一致。
