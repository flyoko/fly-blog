# 资金观察连续流向设计

## 背景

“资金观察 → 板块资金”已经按交易日持久化行业/概念板块的主力净流入 `main_net_inflow`，并返回今日、周累计与窗口累计。新增能力需要在每个板块行中显示当前主力资金已经连续净流入或连续净流出多少个交易日。

## 目标

- 以每日 `main_net_inflow` 正负作为唯一方向口径。
- 在现有 `/api/market/sector-flows` 返回值中统一计算连续流向，前端只负责展示。
- 资金表格新增“连续流向”列，显示 `连续流入 X 天` / `连续流出 X 天`。
- 对历史不足或中间缺失的数据不伪造精确天数。
- 不新增数据源、不新增 D1 表、不改变现有周累计和窗口累计口径。

## 数据口径

### 方向

- `main_net_inflow > 0`：流入。
- `main_net_inflow < 0`：流出。
- `main_net_inflow === 0`：中性，连续计数为 0。
- `main_net_inflow === null`：不可判断，连续计数为 0。

### 连续性

从当前板块最新数据日开始，按 A 股实际交易日逆序检查：

1. 最新日为正，则只继续接受正值；最新日为负，则只继续接受负值。
2. 遇到方向相反或明确的 0，连续段结束，得到精确天数。
3. 遇到应存在但数据库缺失的交易日、`null`，停止计数，并标记历史不完整；绝不跳过缺口去使用更早记录。
4. 如果在当前保留/查询历史范围内始终没有遇到边界，也标记历史不完整，UI 用 `≥X 天`，避免把“至少 X 天”误报为“恰好 X 天”。

## API 契约

在 `SectorFlowItem` 增加：

```ts
export type SectorFlowStreakDirection = 'inflow' | 'outflow' | 'neutral'

export interface SectorFlowStreak {
  direction: SectorFlowStreakDirection
  days: number
  complete: boolean
}
```

并增加字段：

```ts
streak: SectorFlowStreak
```

语义：

- `direction = neutral` 时 `days = 0`、`complete = true`。
- `complete = true` 表示已经观察到明确边界（反向或 0），天数可精确表述。
- `complete = false` 表示在已知连续段之后遇到历史缺口/空值或触达当前历史范围边界，只能表述为“至少 N 天”。

## 后端实现

复用 `MarketService.decorateSectorWindows()` 已经读取的 `market_sector_flow_daily` 历史，不增加额外 D1 请求。

新增纯函数负责：

- 从 `anchorDate` 生成最多 20 个实际 A 股交易日（复用 `isChinaAShareTradingDate`）。
- 逐日读取 `Map<trade_date, main_net_inflow>`。
- 计算 `{ direction, days, complete }`。

当前 live 数据仍覆盖 `anchorDate` 的同日持久化快照，以页面看到的“今日主力”与 streak 起点保持一致。fallback/stale 路径仍通过同一装饰函数，因此契约一致。

## 前端设计

“板块资金”表格列顺序调整为：

`板块 | 涨跌 | 今日主力 | 连续流向 | 本周 | 上周 | 前2周 | 前3周`

连续流向展示：

- 流入且完整：`连续流入 4 天`
- 流出且完整：`连续流出 3 天`
- 流入但历史未闭合：`连续流入 ≥20 天`
- 流出但历史未闭合：`连续流出 ≥6 天`
- 中性/最新值缺失：`暂无连续`

颜色沿用 A 股页面现有语义：流入使用上涨/正向色，流出使用下跌/负向色，中性使用弱化文本色。表格本身已经支持横向滚动；新增列后仅调整最小宽度和 streak 单元格最小宽度，移动端不另造卡片布局。

## 错误与边界处理

- 无历史记录：只使用 live 当日值；若当日非 0，则显示 `≥1 天`，不假装知道前一交易日。
- 历史中间缺日：在缺口处停止，显示 `≥N 天`。
- 历史值为 `null`：在该日停止，显示 `≥N 天`；若最新日为 `null` 则 `暂无连续`。
- 最新日为 0：`暂无连续`。
- 不跨周末和法定休市日制造缺口，交易日判断复用现有 A 股日历。

## 测试

后端覆盖：连续流入、连续流出、方向反转、0 中断、null 中断、缺失交易日不跨越、只有当日数据、20 日范围未闭合；所有场景都必须验证 `complete` 是否与“精确/至少”语义一致。

前端契约测试覆盖：存在“连续流向”列、使用 `item.streak`、三种文案、方向样式、移动端最小宽度调整。

发布前继续执行现有 source/build/mobile E2E/mobile visual 生产门禁。

## 非目标

- 本次不增加“按连续天数排序/筛选”。
- 本次不增加单只股票连续资金流向。
- 本次不改变资金数据源和抓取频率。
- 本次不扩大历史保留期；超过当前可证明范围时用 `≥N 天` 表达。
